Coaching the Coach

Can an AI coach teach itself to coach better?

Picture two AIs. The player solves visual logic puzzles. The coach studies where the player goes wrong and rewrites the player's code to make it better. The twist: we also let the coach rewrite its own code, so it could learn to coach better. Then we tested whether a self-improved coach actually trains better players.

Short answer: no. On a final exam of 120 puzzles none of them had seen before, coached players scored about the same as a player with no coaching at all. What did help was much simpler: letting the model think longer before answering beat every kind of coaching.

How the experiment works

The player is a short program that solves each puzzle using at most two calls to an AI model.11In the repository, the "player" is the task agent and the "coach" is the meta agent. Both run on the same model. The coach runs on the same model. It looks at how the player did on 25 practice puzzles, then edits the player's code to fix what went wrong. One round of this (play, review, edit) is called a generation. In step 1, the coach is also allowed to edit its own code, so in principle it can get better at coaching.

We ran step 1 6 separate times, for 12 generations each. To test a coach, we froze it so it could no longer change (either the original coach or the self-improved one from each run22From each run we took the self-edited coach whose players improved most on practice. This rule was fixed before any exam result existed.). We then handed it a fresh, untouched player and gave it 8 rounds of coaching on a different set of 25 practice puzzles. The finished player sat the exam exactly once: 120 puzzles it had never seen.33The 120 public ARC-AGI-2 evaluation tasks [1], with 167 test inputs. A puzzle with several test inputs earns partial credit.

We also needed something to compare against. The uncoached player sat the same exam as it was, and once more with the model set to think longer: one notch higher on its "reasoning effort" setting, which lets the model reason more before it answers. It still got only two calls and two answers per puzzle. That setting was locked, so no coach could change it.44A gateway that no agent could edit fixed the model, its reasoning effort (high; xhigh for the think-longer run), the call cap and the budget.

What the puzzles look like

The puzzles come from ARC-AGI-2, a set designed to test whether an AI can pick up a new rule from just a few examples. Each puzzle shows a few input→output pairs of coloured grids. You work out the hidden rule, then paint the output for a new input, cell by cell. Try one yourself.

The result

Players trained by the original coach scored +0.4 points above the uncoached player, and players trained by a self-improved coach −1.4 points. Both gaps are smaller than ordinary run-to-run noise, the amount scores bounce around when you simply run the same setup again. In other words, we can't tell either one apart from no effect.5595% intervals: original coach minus no coach [−1.9, +2.8] points; self-improved minus no coach [−4.0, +1.3]; self-improved minus original −1.8 [−4.2, +0.6]. All include zero, which means "no difference" fits the data. Welch t-intervals [2]; the headline was pre-registered. Thinking longer, by contrast, added about 12 points.

How well does a coach improve, and does it get better at improving?

Agent plasticity is how efficiently an agent turns experience into gains on tasks it has not seen [3]. Here we measure it one level up, for the coach.

  • First-order plasticity: how well a coach improves the player. Freeze a coach, let it improve a fresh player for 8 rounds, and compare that player's exam score with the uncoached player's. This is the improvement@k measure from the Hyperagents paper [4], with k = 8 rounds. The original coach: +0.4 points (95% interval [−1.9, +2.8]).
  • Second-order plasticity: whether the coach gets better at improving. Does that first-order gain grow as the coach rewrites itself? Compare players trained by later coaches with players trained by the original coach. Self-improved coach minus original: −1.8 points (95% interval [−4.2, +0.6]). Generation-40 coaches minus original: +0.6 points (95% interval [−6.5, +7.8]).

Here both are indistinguishable from zero: coaching did not measurably improve the player, and rewriting itself did not make the coach a better coach. “Second-order plasticity” is our own name; the Hyperagents paper calls a coach rewriting itself metacognitive self-modification. That paper's positive result comes from moving evolved coaches to a new kind of task. Ours is a same-task test on ARC-AGI-2, so it does not directly test that claim.

The definitions, precisely

Notation, following the Hyperagents paper [4]: a task agent \(A\) (our player) solves tasks; a meta agent \(M\) (our coach) modifies agents and generates new ones; \(\mathcal{G}\) is the agent-generation loop; \(\mathrm{Eval}(A, T)\) is the score of \(A\) on a task set \(T\).

Agent plasticity [3]

Held-out score gain per unit of learning cost, from checkpoint \(0\) to checkpoint \(t\):

\[ P_t \;=\; \frac{S_t - S_0}{C_t} \]

Improvement@k [4]

Hold \(M\) fixed and let it generate up to \(k\) task agents \(\mathcal{A}^{(k)} = \{A_1, \dots, A_k\}\), starting from \(A\):

\[ \mathrm{imp@}k(M, A, \mathcal{G}, T) \;=\; \max_{A' \in \mathcal{A}^{(k)}} \mathrm{Eval}(A', T) \;-\; \mathrm{Eval}(A, T) \]

First-order plasticity of a coach (this study)

Freeze coach \(M\) and run \(k = 8\) rounds from the fresh player \(A_0\) on the practice set. \(\hat{A}_{M}\) is the finished player, chosen on practice puzzles only (the untouched \(A_0\) is a candidate too), and \(T_{\text{exam}}\) is the 120-puzzle exam. Runs are random, so we take the expectation over runs:

\[ \Delta_1(M) \;=\; \mathbb{E}\big[\mathrm{Eval}(\hat{A}_{M}, T_{\text{exam}})\big] \;-\; \mathbb{E}\big[\mathrm{Eval}(A_0, T_{\text{exam}})\big] \]
\[ P_1(M) \;=\; \frac{\Delta_1(M)}{C(M)} \]

\(\Delta_1\) is imp@8 measured on the exam, with the finished player chosen without looking at the exam; \(C(M)\) is the cost of the coaching run.

Second-order plasticity (this study)

Let the coach rewrite itself for \(g\) generations, giving \(M_0 \to M_1 \to \dots \to M_g\), and freeze the coach picked at generation \(g\). Second-order plasticity is the change in first-order plasticity:

\[ \begin{aligned} \Delta_2(g) &= \Delta_1(M_g) - \Delta_1(M_0) \\ &= \mathbb{E}\big[\mathrm{Eval}(\hat{A}_{M_g}, T_{\text{exam}})\big] - \mathbb{E}\big[\mathrm{Eval}(\hat{A}_{M_0}, T_{\text{exam}})\big] \end{aligned} \]
\[ P_2(g) \;=\; \frac{\Delta_2(g)}{C_{\text{evolve}}(g)} \]

\(C_{\text{evolve}}(g)\) is the cost of evolving the coach to generation \(g\). \(\Delta_2 > 0\) would mean the coach got better at improving players.

Our estimates

\(\hat{\Delta}_1(M_0)\) = +0.4 points [−1.9, +2.8]; \(\hat{\Delta}_2(12)\) = −1.8 [−4.2, +0.6]; \(\hat{\Delta}_2(40)\) = +0.6 [−6.5, +7.8]. Each is a difference of run means with a 95% Welch interval [2]. All three intervals include zero, so we do not report the per-cost ratios \(P_1\) and \(P_2\): dividing a gain that cannot be told apart from zero by a cost only adds noise.

Did more generations help?

One reason it didn't: coaches rarely changed themselves. A coach's own code changed in only 21 of 72 generations. We then ran a follow-up that wasn't in the original pre-registered plan (its own plan was written down before it ran). In it, 4 runs kept going to generation 40, and we also tested coaches picked at generations 20 and 40. Often the later pick was literally the same code: in run 1, the coaches picked at generations 12, 20 and 40 were all one version, made back at generation 1.

That one coach scored 26.0%, 27.8% and 36.0% in its three tests. Same code, different scores: that spread is pure noise, and it's bigger than any difference between generations.

What to take away

  • No coach, original or self-improved, trained a player that beat the uncoached one on this exam.
  • Letting the model think longer was worth about 12 points. No coaching came close.
  • Coaches rarely rewrote themselves. And when we tested one unchanged coach three times, its score moved by 10 points, so small differences in this study are just noise.
  • Up close, a coach's edit can make sense and still help only some puzzles. In the traced round, giving the player a self-check on its second try made one puzzle get solved more often, while another was never solved. That's a single round, so it shows how coaching works, not how well it works.

Caveats

  • Noise. Each group had only 3 to 6 runs. One unchanged coach scored 26.0%, 27.8% and 36.0% across three tests, and several later picks were the same code as earlier ones.
  • The original coach needed adapting. With the repository's instruction as written, the model only asked clarifying questions. We added one sentence ("work autonomously") and made tool-call parsing more forgiving. Both kinds of coach started from this adapted version.
  • The original coach often made no edit. It ended 11 of its first 31 rounds without one, mostly because of tool-call formatting problems. As pre-registered, we left this as it was.
  • Some coach edits broke the player. One edit passed an argument the function didn't accept, and that player scored 0. Results like this still count.
  • Re-runs. Bugs in the test harness forced restarts of two original-coach test runs (one of them twice) and cost one self-improvement run a generation. An early 30-minute time limit cut off 49 exam answers for the no-coach and think-longer players; all were re-run with a 2 to 3 hour limit (think longer: 39.9% before, 41.1% after). Six machine restarts lost no results.
  • An untouched final player. In one follow-up test (the generation-20 coach, run 4), the untouched starting player beat the best edited finalist on practice (0.70 vs 0.66). So that exam score is the untouched player's own.
  • Transcripts are partial. They were saved only for failed practice answers (1,513 of them) and contain no hidden reasoning.

Method in full

The design, fixed before any results
  • Question. With equal compute, does a coach that evolved itself train a better player than the original coach?
  • Pre-registration. The plan, the puzzle splits and the analysis code were committed (f577cc7) before any test result existed, so they could not be adjusted to fit the results. The follow-up plan was committed (991a237) before any follow-up test.
  • Model. gpt-6-luna via the OpenAI Responses API, for both player and coach. Reasoning effort was high for both; the think-longer exam used xhigh.
  • Player budget. At most 2 model calls and 2 answers per test input. A test input counts as solved if either answer matches exactly.
  • Coach budget. 600k tokens per coaching round.
  • Spending cap. $150, raised to $200 before the follow-up. Prices: input $0.10, cached input $0.01, output $0.50 per million tokens.
  • Enforcement. A gateway (arcexp/gateway.py) that no agent can edit is the only way to reach the model. It enforces the caps and keeps a ledger.
  • Sandbox. Every test input runs as an unprivileged user, with no network, in a fresh directory, and without access to the answers.
  • Puzzle sets. ARC-AGI-2 commit f3283f7, seed 20261117. The exam is all 120 public evaluation tasks (167 test inputs). The two practice sets have 25 training tasks each and do not overlap.
  • Score. For each task, the share of its test inputs solved, averaged over the 120 tasks (task-averaged pass@2: an input counts if either of the two answers is right).
  • Final player of a run. The two best players are re-scored on practice, the untouched starting player included; the better one sits the exam exactly once.
  • Picking a self-improved coach. Among coaches whose code differs from the original and that have at least one scored child, take the one whose children improved most on average; ties go to the earlier generation.
  • Statistics. 95% Welch t-intervals on per-run exam scores. The headline is the first matching row of a list written in advance.
What was run, in order
  1. No coach. The starting player sat the exam 3 times: 30.1%, 27.9%, 29.7% (average 29.3%).
  2. Think longer. The starting player at xhigh effort, one exam: 41.1%.
  3. Step 1. 6 self-improvement runs of 12 generations. The coach's own code changed in 21 of 72 generations (runs 1 to 6: 1, 4, 5, 1, 7, 3). Run 4 produced no qualifying coach, so 5 self-improved coaches were tested.
  4. Step 2. Original coach, 6 test runs: 26.9%, 29.4%, 30.4%, 30.4%, 31.4%, 29.4% (average 29.7%). Self-improved coaches from runs 1, 2, 3, 5, 6: 26.0%, 27.4%, 31.0%, 27.2%, 27.9% (average 27.9%).
  5. Pre-registered analysis. Original minus no coach +0.4 [−1.9, +2.8]; self-improved minus original −1.8 [−4.2, +0.6]. Headline: "Neither improver beat two plain attempts on ARC-AGI-2."
  6. Follow-up. Runs 1 to 4 continued to 40 generations; coaches picked at generations 20 and 40 were tested under the same rules. Averages at generations 0, 12, 20, 40: 29.7%, 27.9%, 29.8%, 30.3%.
  7. Code audit. 32 changed blocks in the picked coaches: 3 specific to these puzzles, 29 general.
